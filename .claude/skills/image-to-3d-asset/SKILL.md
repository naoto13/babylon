# 画像から3Dアセットを作る

参照画像1枚から、テクスチャ付き glb を作ってアプリへ入れるまでの手順。実測で確立した経路と、そこに至るまでに踏んだ地雷をまとめてある。

**成果物の品質は参照画像でほぼ決まる。** 生成モデルは「見えている面を立体に起こす」だけなので、画像が曖昧なら3Dも曖昧になる。時間配分は「良い参照画像を作る」に厚く置く。

## 向く対象・向かない対象

テクスチャ付きで生成できる経路（ローカル SPAR3D 等）が使えるなら、**装飾的なプロップはほぼすべて AI 生成が有利**。参照画像の意匠がテクスチャとして保存されるため、手続き生成 + 汎用マテリアルでは原理的に出せない情報量が乗る。実測でも、単純な木の板や乳鉢のような地味な対象ですら、質感が付いた瞬間に見違えた。

向かないのは2種類:

- **寸法が意味を持つもの** — 当たり判定そのもの、タイリングする建築物、UI用の板、正確な寸法比が要る機構。手続き生成やモデリングの方が速く確実。生成物は寸法がばらつくので、当たり判定は別途プリミティブで持つ設計にする
- **細い開放構造** — アーミラリ天球儀のリング、鳥籠、格子、鎖、蜘蛛の巣。生成器が最も苦手とする形状で、塊に潰れるか穴が埋まる。**やるなら参照画像側で対策する**: リングや骨組みを実物より太くデフォルメし、構造が読める角度（やや上から見下ろす等）を指定する。生成後は充填率で潰れを確認する（`scripts/check-glb.mjs` が出す）

形状のみ（テクスチャなし）の生成器しか使えない場合は、有機的・装飾的な主役級だけに絞る方が費用対効果が良い。

## 全体フロー

```
① 参照画像を用意（AI生成 or 手持ち写真/イラスト）
      ↓  透過PNG・3/4ビュー・単一オブジェクト
② image-to-3D で glb 生成
      ↓  ローカル SPAR3D が第一選択、クラウドは代替
③ 検証（scripts/check-glb.mjs）
      ↓  UV/テクスチャ/頂点数/サイズを機械確認
④ 必要なら減量（gltfpack）
      ↓  サイズ予算に収める
⑤ アプリへ配置（フォールバック付きローダー推奨）
```

## ① 参照画像

### AI生成する場合のプロンプト定型

この定型が品質を大きく左右する。要素を削ると生成3Dが崩れやすい。

```
共通様式: <作品のアートスタイル>の3Dプロップ参照画像。
単一オブジェクト（または一体化した小群）のみ、画面中央、斜め45度の3/4ビュー、全体が完全に収まる。
背景は完全な透明（アルファチャンネルの真の透過PNG）。均一で柔らかい照明。
色付きドラマチック照明・文字・ロゴ・人物は入れない。
画像内容: <対象物の具体的な説明。素材・色・装飾・形状の特徴>
```

各指定の理由:

- **3/4ビュー**: 正面のみだと奥行きが推測できず板状になる。真横・真上も同様に情報が足りない
- **透過背景**: 生成器は背景除去（rembg）を内蔵するが、自前で透過を渡す方が輪郭が正確。不透明背景でも動くが、床の影や壁を物体の一部と誤認することがある
- **均一照明**: 強い陰影はテクスチャに焼き込まれてしまう。ゲーム側でライティングするなら、素の色情報が欲しい
- **単一オブジェクト**: 複数物体は1つのメッシュに融合されて破綻する。「3本まとまった瓶」のように**一体の群として意図する**場合のみ複数可
- **文字なし**: 判読不能な文字が焼き込まれて安っぽくなる。装飾的な線として指示する方が良い

`scripts/gen-ref-image.sh` が gen-image スキル（codex + gpt-image-2）経由でこの定型を適用する。他の画像生成手段があるならそれでも良い — 定型さえ守れば結果は同等。

### 手持ち画像を使う場合

背景が複雑・被写体が小さい・強い影があるなら、先に画像編集で切り抜くか、背景差し替えで生成し直す方が結局速い。

### スタイルの一貫性

同じシーンに並べるアセットは、**同じ様式指定の文言を全アセットで共有する**。1体だけ写実、1体だけトゥーンになると場が壊れる。プロジェクトごとに「共通様式」の一文を決めて使い回す。

## ② 3D生成

### 生成器の選択

| 環境 | 選択 | 特性 |
|---|---|---|
| Apple Silicon Mac (統合メモリ24GB+) | **SPAR3D ローカル** | 無料・無制限・**テクスチャ+UV付き**・1体2〜3分。第一選択 |
| GPU なし / セットアップ回避 | Hunyuan3D-2.0 の HF Space REST | 無料枠あり・**形状のみ**（テクスチャ生成は拒否される）・要HFトークン |
| 品質最優先で課金可 | Meshy / Tripo | 無料枠は**エクスポート不可**の実績あり。有料前提で考える |

初回はローカル環境の構築が要る。`references/spar3d-setup.md` に手順と既知バグの回避策がある（上流リポジトリが更新停止しており、素の README 通りでは動かない箇所が複数ある）。

クラウド経路は `references/cloud-fallback.md`。

### ローカル生成（SPAR3D）

```bash
<spar3d_root>/run-spar3d.sh <参照画像.png> <出力ディレクトリ>
# → <出力ディレクトリ>/0/mesh.glb がテクスチャ付き glb
```

複数体は `scripts/spar3d-batch.sh` でまとめて回す（モデルのロードが1回で済むぶん速い）。バッチ中に1体失敗しても他は続行する。

テクスチャ解像度は主役級のみ1024、小物は512で十分。上げるとファイルサイズが線形に増える割に、ゲーム内の見え方はあまり変わらない。

## ③ 検証

生成直後に必ず機械確認する。目視だと「UVがない」「テクスチャが入っていない」を見落とす。

```bash
node <skill>/scripts/check-glb.mjs <生成された.glb>
```

出力: 頂点数・面数・属性（POSITION/NORMAL/TEXCOORD_0）・テクスチャ枚数・マテリアル数・bbox・ファイルサイズ。

見るべき点:

- **TEXCOORD_0 と images がある** → テクスチャ付き。そのままマテリアルを使える
- **POSITION のみ** → UV も法線もない白メッシュ。この場合はアプリ側で法線再計算 + トライプラナー投影などの手当てが要る（`references/integration.md`）
- **頂点数が10万超** → 減量を検討
- **bbox が極端に扁平** → 生成が板状に崩れている。参照画像かモデル選択を見直す
- **充填率**（体積 ÷ bbox体積）→ 開放構造の潰れ検出。リングや取っ手のある物は5〜25%に出る。骨組みを意図したのに45%超なら中身が詰まった塊になっている。逆に壺や球のような塊は高くて正常

## ④ 減量

Web配信ならサイズ予算を先に決める。目安: 小物1MB以下、主役級3MB以下、シーン全体で20〜40MB。

```bash
pnpm dlx gltfpack -i in.glb -o out.glb -si 0.2   # 面数を20%へ簡約 + 量子化
pnpm dlx gltfpack -i in.glb -o out.glb           # 量子化のみ（形状はそのまま）
```

`-si` は0.1〜0.3が実用域。実測では17.8MB/100万面 → 2.7MB/18万面で見た目の劣化はほぼ判別不能だった。

テクスチャ付き glb を強く簡約するとUVが乱れることがある。減量後は必ず再検証し、可能ならアプリ上で目視する。

## ⑤ アプリへ配置

**config駆動 + フォールバック**の形にしておくと、生成のやり直しが安全になる。

- glb を決まったパスに置くだけで差し替わる
- ファイルが無い/壊れている場合は手続き生成のプレースホルダ等に自動で落ちる（1体の失敗でシーン全体が死なない）
- 位置・回転・スケールは設定として外に出す

Babylon.js での実装例、テクスチャ有無でのマテリアル分岐、手動レイアウト編集モードの作り方は `references/integration.md`。

## 落とし穴（実測で踏んだもの）

**生成が板状レリーフになる** — 参照画像が正面すぎるか、生成器側の設定が簡易モードに落ちている。3/4ビューの画像で再生成する。

**同じ参照画像なのに前のアセットと同一のglbが出る** — バッチスクリプトの変数取り違えなど、こちら側の事故を疑う。`shasum` で重複を確認する癖をつける。

**ブラウザで差し替えたはずのglbが反映されない** — 静的サーバのキャッシュ。開発中は no-store ヘッダを返すサーバを使う（`references/integration.md` にワンライナー）。

**クラウド生成が突然エラーになり続ける** — 無料GPU枠の枯渇がほとんど。認証トークンを付けると解消することがある。リトライは間隔を空ける（連打は無意味）。

**ローカル生成が「CPUバックエンド未実装」で落ちる** — ネイティブ拡張が誤った環境でビルドされている。`references/spar3d-setup.md` の再ビルド手順を参照。

**手前に置いたアセットが画面に映らない** — 固定カメラの画角外。ワールド座標の勘に頼らず、実際にレンダリングして確認しながら詰める。

## 量産のコツ

- 参照画像生成は**並列**で回せる（画像生成は独立）。3D生成は同一GPU/メモリを使うので**直列**が安全
- 1体ごとに検証を挟むより、バッチで全部作ってから一括検証する方が速い
- 失敗した1〜2体は後でまとめて作り直す。バッチ全体をやり直さない
- 生成した glb と参照画像はセットでリポジトリに入れる（再現性のため。参照画像は数百KB〜2MBなので許容範囲）
