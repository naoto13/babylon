# アセットパイプライン知見の集約運用

`docs/asset-pipeline-history.html`（変遷史＋知見索引ハブ）を最新に保つための運用手順。
知見は書く場所がバラけると死ぬ。**どこに書いた場合でも索引ハブへ1行残す**のがこの運用の核。

## いつ発火するか

以下のどれかに該当したら、作業の完了報告の前にこのスキルの手順を実行する。

- **アセット作業の完了時**: 新規生成・再生成・圧縮設定の変更・ゲームへの組込差し替えを終えたとき
- **新たな落とし穴を解決したとき**: 実際に踏んで、原因を特定し、解決したもののみ。未解決の推測は書かない
- **経路・ツールの採用/打ち切りを決めたとき**: 生成器の乗り換え、クラウド/ローカルの切り替え、パイプライン工程の追加・廃止

## 何を書くか（証拠要件）

書く前に証拠を確定させる。証拠のない記述は追記しない。

- **git hash**: コミット後に `git log --oneline -1` で確定してから書く。コミット前の hash 予測や記憶頼みの hash は禁止
- **実測値**: 必ず単位付きで書く（例: 「24.6MB→1.85MB」「1体2〜3分」）。「大きい」「速い」だけの形容は不可
- **打ち切り**: 「何を試し」「どの閾値に届かず」「証拠はどこにあるか」の3点セットで書く。3点揃わないなら打ち切りとして記録しない

## どこに書くか（判定表）

| 知見の種類 | 書く場所 |
| --- | --- |
| リポジトリ横断の経路変更・打ち切り | `docs/asset-pipeline-history.html` §3（時系列追記）＋ §5（打ち切り表） |
| プロジェクト固有の手順・実測・判定基準 | 当該プロジェクトの `docs/*.html` か `assets/README.md` |
| 環境・ツールの再利用可能手順（同じ穴に二度落ちる系） | `.claude/skills/`。**既存スキルへの追記を新設より優先する** |

**どこに書いた場合も、`docs/asset-pipeline-history.html` §6 の索引へ1行追加は必須。**
索引に載っていない知見は存在しないのと同じになる。

## 書き方

- §3 は時系列 append のみ。既存節の書き換えは事実誤りの訂正に限り、訂正は日付付き note（`<div class="note">2026-MM-DD 訂正: ...</div>`）で行う
- 節の型は「動機 → やったこと → 実測・学び → 乗換/打ち切り理由」。テンプレは history §7 にある
- 詳細は1箇所にだけ書き、他は参照（docs/ からの相対リンク、スキルはパス表記）で繋ぐ。同じ実測表を2箇所に複製しない
- 反映後は `python3 tools/serve.py 4173` で開いて目視し、リンク切れがないか確認する
