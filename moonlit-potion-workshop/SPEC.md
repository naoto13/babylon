# 月夜のポーション工房 仕様ドラフト

Status: Concept / MVP draft 0.1

## 1. ゲーム概要

客の言葉と持ち込まれた素材から目的を推理し、手作業で一瓶を調合する一人称クラフトシミュレーター。完全なレシピ暗記ではなく、効能、安定度、持続時間、副作用を調整して「この客に渡せる答え」を作る。

一言で表すと、`Potion Craftの推理 × 物理的な手触り × 短編ドラマ`。

## 2. 体験目標

- 机上の道具を触ること自体が気持ちよい
- 客の曖昧な言葉から、必要な効能を自分で発見できる
- 失敗作も別の用途や別の客へ回せる
- 1件3〜5分で小さな物語が完結する

## 3. 対象環境

- Primary: PCブラウザ、マウス中心
- Secondary: タブレット、タッチ操作
- Later: ゲームパッド。ポインター移動の補助が必要
- 目標フレームレート: 60fps

## 4. カメラ

- 作業台または接客カウンターへ固定した一人称
- 首振りは左右30度、上下20度程度
- 操作対象を選ぶと、カメラが小さく寄って焦点を合わせる
- 対象を手放すと、同じ経路で元の位置へ戻る
- 大きな視点揺れと自動カメラ移動は避ける

### 判断: 工房内の自由移動はMVPに入れない

メリット:

- 道具と素材の操作品質へ開発時間を集中できる
- カメラ酔いと操作迷子を防げる
- 机上の高品質なライティングとPBRを安定させやすい

デメリット:

- 自分の工房を歩く没入感が弱い
- 探索や隠し素材の発見を作りにくい

本作の独自性は作業と推理にあるため、MVPは固定作業台を推奨する。工房拡張後に複数ステーション間の移動を検討する。

## 5. コアループ

1. 客の依頼と持込品を観察
2. 発言、見た目、時間帯から必要条件を推理
3. 素材を2〜4個選択
4. 切る、潰す、加熱する、混ぜる
5. 試薬または観察で効能と安定度を鑑定
6. そのまま納品、調整、保留のいずれかを選択
7. 客の後日談、評判、素材解放へ反映

想定テンポ:

- 注文と観察: 45〜60秒
- 調合: 2〜3分
- 鑑定と納品: 30〜60秒
- 1夜: 4〜6件、約20分

## 6. 操作

| 入力 | 動作 |
| --- | --- |
| 左クリック／タップ | 掴む、選ぶ |
| ドラッグ | 道具操作、注ぐ、混ぜる |
| ホイール／ピンチ | 対象へ寄る、量を微調整 |
| 右クリック／2本指 | 手放す、操作を戻す |
| Esc | 一段階戻る、メニュー |

操作には吸着と補助回転を入れる。完全な物理自由度より、意図どおり扱えることを優先する。

## 7. 調合モデル

素材は次のプロパティを持つ。

- 主効能: 鎮静、覚醒、治癒、変身など
- 補助効能: 持続短縮、増幅、方向付け
- 適温帯
- 前処理: 切断、粉砕、乾燥
- 相性タグ
- 副作用候補

完成品は次の値で評価する。

- 効能一致度
- 安定度
- 効力
- 持続時間
- 副作用
- 希少性と販売価値

### 判断: 完全な連続物理ではなく状態モデルを推奨

メリット:

- 結果を再現でき、プレイヤーが学習可能
- ブラウザ性能とデバッグ性が安定する
- 注ぐ・混ぜる見た目だけを高品質にできる

デメリット:

- 本物の流体ほど予想外の挙動は生まれない
- 同じ手順の反復が見えやすい

入力値は連続量として受け取るが、内部では意味のある段階へ丸める。例: 温度は数値表示しても、判定は低温・適温・高温の3帯とする。

## 8. レシピと発見

### 判断: 作者設定レシピ＋限定的な創発を推奨

メリット:

- 客の物語に合わせた確実な結果を作れる
- 正解のヒントと学習曲線を設計できる
- 副作用の組み合わせで意外性を残せる

デメリット:

- 無限の組み合わせにはならない
- データ制作量が増える

主効能は作者設定レシピで保証し、量・温度・順序・追加素材により持続時間と副作用を変化させる。

## 9. 注文例

- 眠りたいが夜明けには起きたい配達人
- 声を失わずに一晩だけ嘘をつけなくなりたい役人
- 雨の間だけ人間の姿になりたい水辺の精霊
- 怪我を治したいが戦いの記憶は消したくない騎士
- 花を咲かせたいが成長を早めすぎたくない庭師

依頼には「必須条件」「避けたい結果」「隠れた事情」を1つずつ持たせる。

## 10. 画面

- 注文受付と会話
- 作業台
- 素材棚／図鑑
- 鑑定結果
- 納品と後日談
- 工房設備アップグレード
- 設定／アクセシビリティ

MVPのクリック型プロトタイプでは、注文受付、作業台、鑑定結果の3状態に絞る。

## 11. Babylon.js実装方針

- 選択: Picking＋Highlight Layer
- 直接操作: Pointer Drag Behavior＋独自の吸着補助
- 道具: 回転軸や可動範囲を制限した物理ジョイント
- 液体: 実流体ではなく、液面メッシュ、色、粘度表現をシェーダーで変更
- 素材投入: 粒子表現と内部状態更新を分離
- カメラ: ステーション単位の固定Transformと焦点寄りアニメーション
- セーブ: レシピ発見、客の結果、工房設備をローカル保存から開始

## 12. フィードバック

- 掴んだ瞬間に輪郭と小さなスケール反応
- 適温帯へ入ると炎と液面の音が調和
- 危険域では色だけでなく泡、音、道具振動で警告
- 完成時は派手な演出より、液面が静まる、香りの粒子が整うなど因果の分かる反応
- Reduced motionではカメラ寄りを短いクロスフェードへ置換

## 13. パフォーマンス予算

- 同時インタラクティブ物体: 25個以下
- 高精細表示する主対象: 常に1〜3個
- テクスチャ: 主道具のみ2K、背景棚はAtlas化
- 反射: 動的反射は鍋と主要瓶へ限定
- 初回ロード: 圧縮後20MB以内をMVP目標

## 14. MVP

含める:

- 接客カウンター1か所
- 作業台1台
- 道具5種
- 素材8種
- 注文12件
- 主効能4種
- 副作用12種
- 鑑定、納品、後日談
- マウス／タッチ

含めない:

- 工房内自由歩行
- 完全な流体シミュレーション
- オンライン共有
- 栽培や素材採集
- 価格交渉

## 15. 成功判定

- 初見ユーザーが説明なしで素材を掴み、道具を使える
- 注文文から必要条件を最低1つ正しく推理できる
- 不完全な結果でも「なぜそうなったか」を理解できる
- 1件終了後、別素材または別温度を試したいと感じる

## 16. 未決事項

- 客との会話を選択肢式にするか、観察中心にするか
- 失敗作を保存して別の依頼へ転用できる範囲
- 素材量を数値表示するか、見た目と道具だけで判断させるか
- レシピ図鑑に正解を記録するか、プレイヤーの実験結果だけ記録するか

推奨は「会話選択肢は1〜2問だけ、残りは観察」。会話分岐を増やすより、3D空間の証拠を読む体験へ制作量を集中できる。
