# Potion Economy

## Background

月夜のポーション工房は、依頼を解く一回完結型の錬金ゲームとして実装済みだが、通貨・在庫・工房購入・素材ランクの循環を持たない。PR #3 が差し替える GLB 35 点を、単なる背景ではなく少しずつ手に入る工房アセットとして扱い、低レアリティの錬金から上位素材・高額な成果物へ到達する継続プレイの経済を加える。

## Goals

- 初回プレイで、釜と基本素材だけから錬金して売却し、最初の工房アセットを買える。
- 全36点（既存の `cauldron.glb` を含む）の工房アセットをゲーム内市場で個別購入でき、未購入品は場面に表示しない。
- 購入済みアセット数を工房ランクとして扱い、素材棚と成果物のレアリティを段階的に解放する。
- 依頼への納品と、鑑定済みの瓶を市場へ直接売却する経路を両方成立させる。低品質品にも最小買取額を設定し、試行や失敗で進行不能にならない。
- 通貨、在庫、所有アセット、進行は既存のローカルセーブへ永続化し、旧セーブを破棄しない。

## Recommended Economy Settings

| 項目 | 推奨設定 | 根拠 |
| --- | --- | --- |
| 開始状態 | 36月貨、月光花びら3・霧葉3、釜のみ所有 | 初回の正しい基本錬金を2〜3回試せ、最初の装飾品を無理なく買える。 |
| 素材ランク | Common: 月光花びら/霧葉、Uncommon: 銀苔/苦根/露珠、Rare: 陽羽根/蛙鱗茸/星塩 | 既存8素材の役割と既存レシピを変えずに三段階の発見を作る。 |
| 素材価格 | Common 4、Uncommon 12、Rare 28 月貨 | Great 品を作れば各段階で材料費を上回り、失敗品でも再試行へ戻れる。 |
| 解放条件 | 釜のみ=Common、所有3点=Uncommon、所有8点かつUncommon品を2点所有=Rare | 小さな購入目標を作りつつ、全点収集を次段階の必須条件にしない。 |
| 買取額 | Common 18 / Uncommon 48 / Rare 115 を基礎に、great x1.5、ok x1.15、fail x0.4。依頼成功時は同ランクの報酬 6 / 13 / 30 を加算 | Common の基本レシピ（材料費8）が成功時に次の購入へ向けて純増し、上位帯で資産曲線が急すぎない。 |
| 工房アセット価格 | Tier 1: 24–45、Tier 2: 65–105、Tier 3: 145–220 月貨 | 最初の数回で見た目の変化を得られ、Rare 到達には複数の成功と計画が必要になる。 |
| 詰み防止 | 購入後も現在解放済みの最安素材2個分を必ず残す。市場売却には最小額を設ける。 | 誤購入や失敗で、次の錬金を始められなくなる状態を防ぐ。 |

## Functional Design

### Economy state

`save.js` のバージョンを上げ、以下をゲーム状態に加える。

```js
economy: {
  coins: 36,
  inventory: { "moon-petal": 3, mistleaf: 3 },
  ownedAssetIds: ["cauldron"],
}
```

在庫は投入時に予約し、売却・納品・保留で消費する。未鑑定の調合を戻る・やり直す場合だけ予約分を戻す。旧v1セーブは評判、日誌、保留棚、進行を保ち、開始キット相当の経済状態を付与してv2として読み込む。

### Asset catalog and workshop rank

- カタログは `scene.js` の `HERO_ASSETS` と `DRESSING_ASSETS` の全36点を、ファイル名・表示名・市場Tier・価格・ランク寄与で一意に定義する。
- `cauldron` は最初から所有し、残る35点は個別に買える。
- 市場Tier 1 は開始時、Tier 2 は所有3点、Tier 3 は所有8点かつTier 2を2点所有で表示する。
- 装飾GLBは購入済みのものだけを表示し、購入直後に対応するアンカーを表示する。操作に必須の釜・まな板・乳鉢・火加減・レンズ・トレイ・瓶は、未購入でも既存の簡易手続きメッシュを操作用に残し、購入後にGLB外観へ置換する。これにより最初の鑑定・売却ループを止めない。ロード失敗時も同じ簡易メッシュへ戻してゲーム操作を継続する。
- 工房ランクは所有数とTier条件から計算する純関数とし、Common / Uncommon / Rare の素材購入可否と成果物ランクに使う。装飾品の購入に戦闘・運要素や隠れた収益補正は加えない。

### Market and selling flow

- トップバーの「市場」から、所持月貨、次の解放条件、素材棚、工房アセット一覧を確認・購入できる。
- 購入不能なカードは理由（未解放、月貨不足、基本素材の予約額を残せない）を表示する。購入済みカードは再購入できない。
- 素材の投入時には在庫が必要で、残数0の素材を選べない理由を通知する。
- 鑑定パネルに「市場へ売却」を追加する。売却すると、使用素材の最高ランクと `great / ok / fail` 品質から買取額を決定し、月貨を加算して作業台へ戻る。
- 既存の依頼納品は維持し、同じ瓶の市場価格に依頼成功報酬を加算する。依頼の評判判定は既存の `judgeDelivery` を変えない。
- 固定12依頼を終えた後は、同じ依頼帳を「巡回依頼」として1件目から再開し、経済ループを継続できる。日誌と所有状態は残る。
- 新規ゲームの釜温度は `low` から始める。月光花びらと霧葉だけでも最初の安定したCommon品を作れ、既存の火加減操作で変更できる。

### Potion valuation

`economy.js` を Babylon/DOM/Storage 非依存の純関数とする。

- `getWorkshopRank(ownedAssetIds)` は資産カタログからランクと次条件を返す。
- `getAvailableMaterials(rank)` は購入可能な素材IDを返す。
- `getPotionOffer(brewInput, brewResult, judgement?)` は最高素材ランク、品質、基礎額、倍率、依頼報酬、最終月貨を返す。
- 品質は依頼の有無によって変えない。納品時は `judgeDelivery` の tier、市場売却時は安定度75以上かつmajor副作用なしをgreat、安定度60以上をok、それ以外をfailとする。
- 金額計算は丸め規則を含めて決定的とし、クライアント時計や乱数を使わない。

## UI and Accessibility

- 市場は既存のモーダルと同じEsc・閉じる操作、フォーカス表示、`prefers-reduced-motion` を尊重する。
- 購入、売却、ランク解放は短いフェードと明確なステータスメッセージで確認する。不要な常時アニメーションは加えない。
- 通貨・在庫・解放条件は数値表示設定にかかわらず市場では明示する。錬金中の既存の数値非表示体験は維持する。
- 小画面では市場カードを一列にし、主要な購入・売却ボタンが隠れない。

## Non-Goals

- 実通貨、課金、オンライン市場、NFT、サーバー同期、ランダムガチャ。
- 既存の錬金評価式、依頼テキスト、3D操作の全面的な作り直し。
- 全36点の購入を必須にするエンディング条件。

## Acceptance Criteria

1. 新規セーブでは釜のみ所有、36月貨、Common素材の開始在庫で始まり、Commonの2素材錬金を鑑定して市場へ売却できる。
2. 市場で全36アセットを個別に確認でき、未解放・不足・予約額の理由が購入ボタンの状態と一致する。
3. Tier 1を3点所有するとUncommon素材、所有8点かつTier 2を2点所有するとRare素材を購入できる。条件未達では購入できない。
4. 各素材ランクについて、指定価格、品質倍率、依頼報酬を使った売却額が純関数テストで検証される。
5. 購入済みアセットはGLB外観で表示され、未購入の装飾アセットは表示されない。未購入の操作必須アセットは簡易メッシュのまま使え、個別GLBのロード失敗でもゲーム操作・市場操作は継続できる。
6. 在庫0の素材は投入できず、未完成の調合を離脱した場合だけ予約在庫が戻る。売却・納品・保留後には戻らない。
7. 誤購入後も最安の解放済み素材2個分は残り、売却失敗品にも最小買取額があるため新しい錬金が可能である。
8. v1形式の有効な既存セーブを読み込んでも、元の進行データを保ったv2経済状態に移行する。
9. `node --test` の既存テストと追加した経済・セーブテストが通り、ブラウザで「開始→売却→アセット購入→素材解放→上位品売却」の一連を確認する。
