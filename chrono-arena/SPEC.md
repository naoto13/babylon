# クロノ・アリーナ 仕様ドラフト

Status: Concept / MVP draft 0.1

## 1. ゲーム概要

60秒の戦闘中に強化を完成させる、固定見下ろし型アクションローグライト。プレイヤーは敵を倒すだけでなく、「残り時間を能力へ変換するか」「次の強化機会まで温存するか」を判断する。

一言で表すと、`Vampire Survivors系の密度 × Hades系の能動操作 × 時間を消費するビルド構築`。

## 2. 体験目標

- 開始5秒以内に操作と危険方向が理解できる
- 30秒でビルドの方向性が見え、60秒で一度完成する
- 敗北しても「次はこの組み合わせを試す」が必ず残る
- 1プレイが短く、ブラウザでURLを開いてすぐ再挑戦できる

## 3. 対象環境

- Primary: PCブラウザ、キーボード＋マウス
- Secondary: PCブラウザ、ゲームパッド
- Later: タッチ端末。仮想スティック追加より、移動先タップ方式を別設計する
- 目標フレームレート: 60fps、低性能端末は30fpsへ段階低下

## 4. カメラ

- 透視投影の高角度3/4見下ろし
- 円形アリーナ全体を原則固定表示
- プレイヤーが外周へ寄った場合だけ、画面中央から最大10%追従
- ズーム操作は持たせず、情報密度を一定にする
- 被弾時の画面揺れは小さく短くし、`prefers-reduced-motion` 相当設定では無効化

### 判断: 固定視点を推奨

メリット:

- 敵密度と危険予告を同時に把握しやすい
- 描画対象とLODを制御しやすく、ブラウザ性能を安定させやすい
- プレイヤーがカメラ操作を覚える必要がない

デメリット:

- 巨大ボスや縦方向の演出に制約が出る
- 探索や発見の感覚は弱い

本作の目的は60秒の高速判断なので、自由カメラより固定視点の利点が大きい。

## 5. コアループ

1. アリーナと初期武器を選択
2. 60秒の戦闘を開始
3. 敵を倒して時間片と経験値を獲得
4. 30秒地点または経験値閾値で時間停止
5. 3つの候補から強化を1つ選択
6. 戦闘へ即時復帰
7. 0秒時点でボスの撃破判定または生存判定
8. 遺物を1つだけ次のランへ継承

想定テンポ:

- 戦闘: 60秒
- 強化選択: 10〜15秒
- 結果: 10秒
- 1セッション: 5〜8ラン、約8〜12分

## 6. 操作

| 入力 | 動作 |
| --- | --- |
| WASD / 左スティック | 移動 |
| マウス / 右スティック | 照準 |
| Space / A | 回避 |
| Q・E・R / トリガー | 能動スキル |
| Esc | ポーズ |

### 判断: 通常攻撃は自動、能力は手動を推奨

メリット:

- 密集戦でも入力負荷を抑えられる
- 移動、回避、能力発動という重要判断へ集中できる
- タッチ対応へ展開しやすい

デメリット:

- 射撃そのものの操作感は弱くなる
- 対象選択AIが不自然だと納得感を失う

照準方向を優先しつつ、範囲内の最短敵へ補正するハイブリッド方式とする。

## 7. 時間システム

- 基本残り時間: 60秒
- 能力の一部はクールダウンではなく残り時間を直接消費する
- 強力な時間能力は1回につき1〜5秒を消費
- 敵撃破時、低確率で0.2〜0.5秒を回復
- 30秒地点では時間を完全停止し、強化選択中に残り時間は減らない

時間消費能力の例:

- `未来斬り`: 2秒消費し、2秒後の敵位置をまとめて攻撃
- `巻き戻し`: 4秒消費し、3秒前のHPと位置へ戻る
- `停止領域`: 毎秒1秒を追加消費し、範囲内の敵だけを停止

## 8. 強化設計

強化は単純な数値上昇ではなく、既存行動の意味を変える。

- 秒針の刃: 移動距離が攻撃力になる
- 因果の環: 同じ対象への連続攻撃が過去の攻撃を再発生させる
- 砂時計の心臓: 残り10秒だけ世界を半速化する
- 逆行装甲: 回避後1秒以内の被弾を無効化し、被弾地点へ衝撃波を残す
- 時間債務: 今すぐ15秒を得るが、次ランの開始時間が10秒減る

## 9. 敵とアリーナ

MVPの敵:

- 追跡獣: 数で圧力を作る基本敵
- 射針兵: 床へ直線予告を出す遠距離敵
- 時盗り: 接触すると残り時間を奪う優先撃破対象
- ボス「暦喰らい」: アリーナ外周から時間帯を封鎖する

アリーナは円形1種類から開始し、障害物より床面テレグラフの読みやすさを優先する。

## 10. 画面

- タイトル／ラン開始
- 60秒戦闘HUD
- 時間停止アップグレード
- ラン結果と持越し選択
- 設定／アクセシビリティ

## 11. Babylon.js実装方針

- 敵群: Thin InstancesまたはSolid Particle Systemを検証
- 移動: 平面上の独自軽量移動。敵同士の完全物理衝突は避ける
- 攻撃予告: 地面デカールまたは薄い動的メッシュ
- エフェクト: GPU Particle System。低設定では粒子数とBloomを削減
- カメラ: 固定Transform＋限定追従。論理座標と演出揺れを分離
- 物理: MVPではHavokを必須にしない
- オブジェクトプール: 敵、弾、ダメージ表示を再利用

## 12. パフォーマンス予算

- 同時敵数: 初期100、上限300を段階検証
- Draw calls: 低設定で150以下を目標
- 初回ロード: 圧縮後15MB以内をMVP目標
- テクスチャ: 2Kを上限、Atlas化を優先
- フレーム時間: 60fps時16.6ms、ロジック＋描画の内訳を常時計測

## 13. MVP

含める:

- アリーナ1種
- 初期武器2種
- 敵3種＋ボス1体
- 強化12種
- 60秒ラン、強化、結果、再挑戦
- キーボード／マウスとゲームパッド
- 低・中・高の品質設定

含めない:

- 複数バイオーム
- オンライン協力
- キャラクタースキン
- 複雑なメタ進行
- モバイル最適化

## 14. 成功判定

- 初見ユーザーが説明なしで10秒以内に移動・回避できる
- 3回以内に異なる強化の組み合わせを自発的に試す
- 60秒終了後の即時リトライ率が50%以上
- 敗北理由を「見えなかった」ではなく「判断を誤った」と説明できる

## 15. 未決事項

- 60秒終了条件を生存にするか、必ずボス撃破にするか
- 遺物持越しを強制するか、時間片への変換も許すか
- 時間消費能力のUIを秒数表示にするか、タイマー外周の欠けで表現するか

推奨は「最初のMVPは生存成功、上位難度でボス撃破必須」。成功体験を早く作りつつ、熟練者向けの明確な目標も追加できる。
