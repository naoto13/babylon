3. 変遷史

各節は「動機 → やったこと → 実測・学び → 乗換/打ち切り理由」の型で書く。 新しい経路を試したら同じ型で末尾に追記する（§7）。

3.1 コンセプト画期（07-22〜23）

動機。どのゲームを作るか決めるため、先に「完成画面のイメージ」を作って比較する。

やったこと。5efec51（first commit, 07-22）で開始し、 421d9ee（07-23）で gpt-image-2 によりゲーム画面イメージ12枚を1案ずつ生成、 ルートの index.html を12案の比較 Atlas として追加した。 生成時の共通条件と各案の最終指示は IMAGE_PROMPTS.md に記録してある。

帰結。12案のうち「Chrono Arena」「月夜のポーション工房」の2本がプロトタイプへ進み、 コンセプト画がその後のアセットの意匠の正本になった。

3.2 SPAR3D 期 — 月夜のポーション工房 全アセット AI 生成（07-24〜29）

動機。コンセプト画で決めた意匠を、手作業モデリングなしでゲームへ入れたい。 Apple Silicon Mac（MPS）のローカルで無料・無制限に回せる image-to-3D として SPAR3D を採用した。

やったこと。ece219f（07-24）で月夜のポーション工房の全アセットを AI 生成に置き換え、tools/spar3d/run-spar3d.sh を追加。 2eef9ff（07-25）で机上アセット10種を追加、 3144711（07-27）で配置エディタ・天球儀アセット・no-cache 開発サーバを導入した。

実測・学び。テクスチャ+UV 付き glb が1体2〜3分で出る （出所: .claude/skills/mac-image-to-3d/SKILL.md）。 参照画像の定型（3/4ビュー・透過 PNG・均一照明・単一オブジェクト）が品質をほぼ決めること、 細い開放構造（天球儀のリング等）が生成器の最も苦手な形状で、 参照画像側で太めにデフォルメし充填率で潰れを検出する運用が、この期に確立した。

乗換理由。プロップ量産には十分だったが、形状精度とテクスチャ品質の限界が キャラクター制作（3.4）で顕在化し、TRELLIS.2 転換（3.5）へ繋がった。

3.3 Chrono Arena Blender 手組み期（07-27）

やったこと。並行して進んだ Chrono Arena は、1f7ad1b（07-27）で Blender 手組みのカスタムアセットによりプレイアブルを出荷した。

帰結。この手組みモデルが以後の生成品質の比較基準になった （写実系生成の打ち切り判定は「実機で現行＝手組みモデルに及ばない」だった。3.4）。 キャラクターの追加・刷新は、以後スクリプト化された生成パイプラインへ移っていく。

3.4 三面図→ねんどろいど風パイプライン（07-29）

動機。Chrono Arena のキャラクターを SF＋悪魔の意匠へ刷新する。 まず写実系の参照画像から SPAR3D で生成する案を試したが、テクスチャの白飛びで意匠が消え、 3方式（そのまま利用／単色ティント／参照画像投影）すべて品質未達で打ち切った （証拠: trellis2_Babylon_chrono-arena/.gitignore の materials/ に付されたコメント「この経路は品質が要求に届かず打ち切った」）。

やったこと。580d118（07-29）でねんどろいど風デフォルメの 三面図パイプライン（キャラ5体）とシーンの質感基盤を追加し、 7167a3f（同日）で hero に16ボーンリグを入れ、制作パイプラインを character-asset-pipeline.html としてドキュメント化した。

実測・学び。デフォルメで参照画像の情報量を減らすほど生成が正確になる。 SPAR3D はアルベドを一定明度へ正規化するため参照画像側では制御できない （入力の平均輝度を 0.216→0.453 に持ち上げても出力は 0.383→0.369 とほぼ不変）。 出力メッシュは非連結サーフェスに断片化しており（hero で 1,386 個）、 リグ前の Voxel Remesh が前提条件になる。 数値基準・落とし穴の詳細は character-asset-pipeline.html §4〜§5 に集約してある。

帰結。三面図＋デフォルメという「型」は確立したが、 SPAR3D 自体の精度限界が明確になり、翌日の TRELLIS.2 転換へ。

3.5 TRELLIS.2 転換（07-30）

転換理由。SPAR3D の出力品質は公開されている最新モデルに明確に劣る。 しかし Mac では TRELLIS.2 がメモリ要件で動作せず、SPAR3D しか選べなかった。 そこで専用の Windows/NVIDIA 機（RTX 4070 SUPER, VRAM 12GB）を用意し、 TRELLIS.2 を ComfyUI（visualbruno/ComfyUI-Trellis2）でローカル実行する経路へ移行した。 ジオメトリ品質が目に見えて向上し、フル PBR テクスチャを生成できる品質差も決め手 （出所: .claude/skills/windows-image-to-3d/SKILL.md、 .claude/skills/mac-image-to-3d/SKILL.md）。

やったこと。c6e47c9（07-30）で hero を TRELLIS.2 生成メッシュ＋ 16ボーンリグへ差し替え、tools/trellis2/（rotate180.py・run_comfyui.sh）を初追加、 スキル2本（glb-compression-pipeline・local-image-to-3d〔現 windows-image-to-3d〕）を追加。 d3763d6 で月夜の釜を差し替え、6003ccd と 852158a で 敵4体（chaser・shooter・thief・boss）をすべて差し替え。 0f7ada2 で image-to-3d スキル〔現 mac-image-to-3d〕をリポジトリへ同梱した。

実測。FP8 量子化モデル（visualbruno/TRELLIS.2-4B-FP8、約8GBダウンロード）が 12GB VRAM に収まる。形状のみ約13分、PBR テクスチャ付き約16分/体（RTX 4070 SUPER）。 gltfpack 圧縮で生出力 24.6MB→1.85MB の実績。

帰結。TRELLIS.2/ComfyUI ローカルが新しい既定経路になった。

3.6 全面移行（07-31）

やったこと。fc79506（07-31）で月夜のポーション工房の 全35アセットを TRELLIS.2 で再生成。tools/trellis2/comfy_generate.py （ComfyUI API 直叩きの生成）と tools/trellis2/pack_for_game.py （gltfpack 圧縮＋配置）を追加し、生成→圧縮→配置がコマンド2本で通るようになった。

実測。models/ フォルダは 42MB→25MB （出所: trellis2_Babylon_moonlight-potion/game/assets/README.md）。 12GB VRAM ではデコード時のピークで OOM しやすいため、連続生成は6点程度ずつに区切り /free を挟む。形状が密で落ち続ける対象は --no-cascade （1024 へのカスケードを外し 512 のままデコード）で通す。 テクスチャは接写・操作対象 1024²、飾り 512²。

帰結。現行パイプライン（§4）の完成形。

3.7 ディレクトリ再編と知見整備（08-16）

やったこと。56e2b24（08-16）でサブプロジェクトを trellis2_Babylon_chrono-arena / trellis2_Babylon_moonlight-potion へリネーム。続く知見整備（feat/asset-knowledge-base）で、スキルを mac-image-to-3d（旧 image-to-3d-asset。SPAR3D 期の内容・非推奨として保存）と windows-image-to-3d（旧 local-image-to-3d。現行既定）の二本立てへ再編し、 check-glb.mjs・gen-ref-image.sh を tools/ へ移設、 本ドキュメントと asset-pipeline-history スキル（更新運用）を新設した。

4. 現行パイプライン（現在地）

既定は Windows/NVIDIA 機での TRELLIS.2（ComfyUI, FP8）。 参照画像1枚からゲーム配置までの流れは次のとおり。

参照画像生成
tools/gen-ref-image.sh→ 3D 生成
tools/trellis2/comfy_generate.py→ 圧縮＋配置
tools/trellis2/pack_for_game.py→ 検証
node tools/check-glb.mjs

コマンドの詳細・環境構築・トラブルシュートは本書には書かない。 生成環境は .claude/skills/windows-image-to-3d/SKILL.md、 gltfpack 圧縮の無音破壊トラップは .claude/skills/glb-compression-pipeline/SKILL.md、 容量予算と運用実測は trellis2_Babylon_moonlight-potion/game/assets/README.md を参照。
