# 月夜のポーション工房 仕様

Status: Implementation draft 0.2（0.1 の未決事項を決定し、調合エンジンと Babylon.js 実装仕様を追加）

## 1. ゲーム概要

客の言葉と持ち込まれた素材から目的を推理し、手作業で一瓶を調合する一人称クラフトシミュレーター。完全なレシピ暗記ではなく、効能、安定度、持続時間、副作用を調整して「この客に渡せる答え」を作る。

一言で表すと、`Potion Craftの推理 × 物理的な手触り × 短編ドラマ`。

## 2. 体験目標

- 机上の道具を触ること自体が気持ちよい
- 客の曖昧な言葉から、必要な効能を自分で発見できる
- 失敗作も別の用途や別の客へ回せる
- 1件3〜5分で小さな物語が完結する

## 3. 対象環境

- Primary: PCブラウザ、マウス中心
- Secondary: タブレット、タッチ操作
- Later: ゲームパッド。ポインター移動の補助が必要
- 目標フレームレート: 60fps

## 4. カメラ

- 作業台または接客カウンターへ固定した一人称
- 首振りは左右30度、上下20度程度
- 操作対象を選ぶと、カメラが小さく寄って焦点を合わせる
- 対象を手放すと、同じ経路で元の位置へ戻る
- 大きな視点揺れと自動カメラ移動は避ける
- 工房内の自由移動はMVPに入れない（0.1の判断を維持）

## 5. コアループ

1. 客の依頼と持込品を観察
2. 発言、見た目、時間帯から必要条件を推理
3. 素材を2〜4個選択し、前処理を決める
4. 切る、潰す、加熱する、混ぜる
5. 鑑定レンズで効能と安定度を確認
6. そのまま納品、調整、保留のいずれかを選択
7. 客の後日談、評判、素材解放へ反映

想定テンポ:

- 注文と観察: 45〜60秒
- 調合: 2〜3分
- 鑑定と納品: 30〜60秒
- 1夜: 4件、約20分。全3夜=12件

## 6. 操作

| 入力 | 動作 |
| --- | --- |
| 左クリック／タップ | 掴む、選ぶ |
| ドラッグ | 道具操作、注ぐ、混ぜる |
| ホイール／ピンチ | 対象へ寄る、量を微調整 |
| 右クリック／2本指 | 手放す、操作を戻す |
| Esc | 一段階戻る、メニュー |

操作には吸着と補助回転を入れる。完全な物理自由度より、意図どおり扱えることを優先する。

## 7. 旧・未決事項の決定（0.1 §16 の解消）

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| 会話 vs 観察 | 選択肢式の質問は1注文につき最大1問。残りは台詞と外見描写から推理 | 分岐制作量を抑え、観察体験へ集中 |
| 失敗作の転用 | 保留棚2枠。同じ夜の別注文へ納品候補として提示できる | ループ内で完結し、セーブ構造が単純 |
| 素材量の数値表示 | 数値非表示。目盛りと見た目で判断。設定で「数値表示ON」を用意 | 手触り優先＋アクセシビリティ担保 |
| 図鑑の記録内容 | 正解レシピは載せない。プレイヤーが実際に作った調合結果のみ記録 | 発見の所有感を守る |

## 8. 調合エンジン仕様（決定版データモデル）

### 8.3 タグ相性（4ルールのみ）

- `solar` × `lunar` 同時使用: 安定度 −20
- `lunar` × `lunar`（2素材以上）: 効力 +5
- `water` × `fungal`: shift 効力 +10
- `earth` × `herbal`: 安定度 +5

### 8.4 調合入力

```js
{
  items: [{
    materialId,
    prep: "none" | "cut" | "crush",
    amount: "scant" | "standard" | "ideal" | "heavy"       // 注ぎ量帯。省略時 "standard"
  }], // 配列順=投入順、2〜4個
  tempBand: "low" | "mid" | "high",                        // 火加減ダイヤルから丸め
  stirLaps: number,                                         // かき混ぜ周回数 0〜10
  technique: {                                              // §8.7。省略時 補正なし
    stirQuality: number,                                    // 0〜100、既定50
    simmer: "none" | "perfect" | "good" | "early" | "late"  // 既定 "none"
  }
}
```

### 8.5 評価式（すべて決定的、clamp 0〜100）

効力 `potency`（主効能素材ごとに計算し、その主効能へ加算）:

- base 50
- 前処理が推奨と一致 +15 / 不一致 −10
- 素材適温帯 = 鍋温度帯（`any`は常に一致） +15 / 不一致 −15
- star-salt が調合に含まれる +20
- 主効能素材が投入順の先頭 +5
- タグ相性の効力補正を適用
- 異なる主効能の素材が2種以上: 各効能 −20（混濁）

安定度 `stability`:

- base 70
- bitterroot +15、タグ相性補正を適用
- 全素材の適温帯が鍋温度帯と適合 +10
- stirLaps < 2: −15（未混合、全効能 −10 も併発）
- stirLaps > 6: 超過1周ごとに −4（えぐみ）
- 素材4個使用: −10
- 混濁発生時: −20

持続 `duration`（3段階 short / mid / long）:

- 基準 mid
- mistleaf（shorten）で1段短縮、star-salt（amplify）で1段延長。両方なら相殺して mid

副作用発現判定（素材ごとの副作用候補が発現する条件、いずれか1つで発現）:

- 最終 stability < 60
- その素材の適温帯が鍋温度帯と不一致
- star-salt 使用中かつその素材が主効能持ち

dewpearl（soften）は発現した副作用のうち投入順が早い素材のもの1つを打ち消す。bitterroot は stability < 80 のとき bitterness を追加発現。

### 8.6 技巧システム（プレイヤースキル反映）

手の動きの巧拙が品質を動かす。連続量の測定は UI 層、帯域への丸めと補正はエンジン層（§7 の状態モデル哲学を維持）。全補正は §8.5 の基礎計算の後、clamp の前に加算する。

**A. かき混ぜ真円度 `stirQuality`（0〜100、既定50）**

- UI層測定: かき混ぜ中の各サンプル点について撹拌中心からの半径を記録。1周ごとに変動係数 `cv = std(r) / mean(r)` を計算し、`lapScore = clamp(0, 100, round(100 − cv × 400))`。平均半径 30px 未満の周回は上限40。`stirQuality` = カウントされた全周回の `lapScore` 平均。周回0なら50（補正なし）
- エンジン補正: 安定度 `+= round((stirQuality − 50) / 10)`（−5〜+5）、各主効能効力 `+= round((stirQuality − 50) / 12.5)`（−4〜+4）

**B. 注ぎ量 `amount`（素材ごと）**

- UI層測定: 瓶を釜上で保持するとゲージが 0→100 で増加（約45/秒）。離した時点の値と素材固有の適量帯 `pourBand`（data.js、狭いほど高難度: star-salt 60-75、moon-petal 50-80 など）で帯域化: `<35 → scant`、`35〜(idealMin−1) → standard`、適量帯内 → `ideal`、超過 → `heavy`
- エンジン補正（主効能素材）: scant 効力−20 / standard 0 / ideal 効力+8 / heavy 効力+5 かつその素材の副作用候補に発現トリガー追加
- エンジン補正（補助素材）: scant 補助効果無効 / standard 0 / ideal 安定度+2 / heavy 補助効果有効だが自身の副作用候補に発現トリガー追加

**C. 煮込みの止めどき `simmer`**

- UI層測定: 素材1個以上投入後、炉の火（または調合サマリーの煮込みボタン）を押し続けると煮込み開始。目標秒数は温度帯依存: low 5.0秒 / mid 3.5秒 / high 2.5秒（高温ほど短く高リスク）。離した時刻の目標との差 `d` で帯域化: `|d| ≤ 0.4 → perfect`、`|d| ≤ 1.0 → good`、`d < −1.0 → early`、`d > 1.0 → late`。実施しなければ `none`
- 視覚キュー: 泡の勢いが目標に近づくほど強まり、目標窓内で釜の縁が金色に輝く。数値表示ONなら経過秒も表示
- エンジン補正: perfect 安定度+8・全主効能+4 / good 安定度+3 / early 全主効能−6 / late 安定度−8（さらに tempBand=high なら sparks 発現）/ none 補正なし

**アクセシビリティ**: 設定「判定をやさしく」（既定OFF）で適量帯幅と煮込み窓を1.5倍（UI層で適用。エンジンは帯域のみ受け取る）。

**フィードバック**: 各ジェスチャー直後に短評（「きれいな円だ」「注ぎすぎた」「ぴったりの火加減だ」等）を status に表示。鑑定パネルに技巧内訳（真円度・素材ごとの注ぎ量・煮込み）を理由行として追加。

### 8.7 納品判定

注文は `required`（必須条件）、`forbidden`（避けたい結果）、`hidden`（隠れた事情）を持つ。

- **大成功**: required 充足 かつ forbidden なし かつ major 副作用なし かつ stability ≥ 75 → 評判 +3
- **納品可**: required 充足 かつ forbidden なし → 評判 +1
- **失敗**: それ以外 → 評判 −1、後日談が変化

hidden は判定に使わず後日談テキストと追加ボーナス（evaluated 条件付き評判 +1）にのみ使う。

## 10. 画面と状態機械

```text
TITLE → NIGHT_INTRO → ORDER（受付・観察・質問1問）
      → CRAFT（作業台）⇄ APPRAISE（鑑定レンズ）
      → DELIVER（納品 / 調整に戻る / 保留棚へ）
      → EPILOGUE（後日談）→ 次の ORDER または NIGHT_END → NIGHT_INTRO …→ ENDING
```

- 保留棚: 2枠。DELIVER で「保留」を選ぶと瓶を棚へ。以後の DELIVER 画面で棚の瓶も納品候補に出す
- 図鑑: APPRAISE 実行のたび、その調合結果（素材・手順・結果値）を記録

## 11. Babylon.js 実装アーキテクチャ（MVP決定版）

### 11.1 ファイル構成（ビルド不要・静的配信）

```text
moonlit-potion-workshop/game/
  index.html        # canvas + DOM オーバーレイ UI
  style.css
  package.json      # {"type":"module"} のみ（node --test 用のモジュール解決マーカー）
  js/
    data.js         # §8-9 の素材・注文・副作用データ（純データ、副作用なし）
    engine.js       # §8.5-8.7 の評価ロジック（純関数、Babylon 非依存）
    save.js         # localStorage（評判・夜進行・図鑑・保留棚）
    ui.js           # DOM オーバーレイ（注文カード・会話・鑑定・後日談）
    scene.js        # Babylon シーン構築（作業台・道具・素材瓶・照明）
    interactions.js # ピッキング・ドラッグ・ダイヤル・かき混ぜジェスチャー
    main.js         # 状態機械と各モジュールの結線
  test/
    engine.test.mjs # node --test で実行する engine の単体テスト
```

- Babylon.js は CDN の UMD 版 `<script src="https://cdn.babylonjs.com/babylon.js"></script>`（グローバル `BABYLON`）
- 3Dアセットは外部ファイルなし。全メッシュ MeshBuilder による手続き生成＋DynamicTexture ラベル

### 11.2 シーン

- カメラ: `UniversalCamera` 固定位置。pointermove で yaw ±30°/pitch ±20° の首振り。対象選択時は補間で小さく寄る（`prefers-reduced-motion` 時はクロスフェード相当の短時間切替）
- 作業台: 天板、鍋（釜）、まな板＋ナイフ、乳鉢＋乳棒、火加減ダイヤル、鑑定レンズ、納品トレイ
- 素材棚: 奥に8瓶。DynamicTexture で和名ラベル
- 液体: 鍋内の円盤メッシュ。色=支配的効能、粘度=安定度で波アニメ振幅、温度帯で泡パーティクル量
- 照明: 月光の directional + 炉の point light（温度帯で強度・色変化）+ 弱い hemispheric

### 11.3 インタラクション

- 選択: シーンピッキング + `HighlightLayer`
- 素材投入: 瓶をドラッグ → 鍋上のドロップゾーンで吸着 → 投入演出（パーティクル）と内部状態更新を分離
- 前処理: 瓶をまな板/乳鉢へドラッグ → その場で短いドラッグ往復（切る）/ 円ドラッグ（潰す）ジェスチャー
- 火加減: ダイヤルを回転ドラッグ → 連続角度を low/mid/high に丸め、UI に段階表示
- かき混ぜ: 鍋上で円ドラッグ → 周回数を `stirLaps` としてカウント（過剰周回は液面が濁る警告表現）
- 鑑定: レンズをクリック → engine 評価 → DOM パネルへ結果

### 11.4 パフォーマンス予算（0.1 §13 継承）

- 同時インタラクティブ物体 25個以下、高精細主対象 1〜3個
- 動的反射は鍋と主要瓶のみ、初回ロード圧縮後 20MB 以内（手続き生成のため実質 Babylon 本体のみ）

## 12. フィードバック

- 掴んだ瞬間に輪郭と小さなスケール反応
- 適温帯へ入ると炎と液面の音が調和（MVPは視覚のみ、音は後続）
- 危険域では色だけでなく泡、道具振動で警告
- 完成時は派手な演出より、液面が静まる、香りの粒子が整うなど因果の分かる反応
- Reduced motion ではカメラ寄りを短いクロスフェードへ置換

## 13. MVP範囲

含める: 作業台1台、道具5種、素材8種、注文12件（3夜）、主効能4種、副作用12種、鑑定・納品・後日談、保留棚2枠、図鑑、ローカルセーブ、マウス／タッチ。

含めない: 工房内自由歩行、完全流体、オンライン共有、栽培・採集、価格交渉、音響（後続）。

- 実行時生成の DynamicTexture が白サンプルされる環境問題（Orca 埋め込みブラウザで再現。夜空はジオメトリ構成で回避済み。起動時生成のラベル/鉄テクスチャは正常）

- 注文文から必要条件を最低1つ正しく推理できる
- 不完全な結果でも「なぜそうなったか」を理解できる（鑑定パネルが根拠を短文表示）
- 1件終了後、別素材または別温度を試したいと感じる
